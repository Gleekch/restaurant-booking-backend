# Staff UI release

Base: bc093a0. Scope: premium desktop and protected tablet/mobile administration.
The public customer website is not part of this release.

- Authentic SVG spiral, bundled Manrope/OFL, teal and sand palette.
- Financial actions and old arrival/completion action are disabled, with visible
  explanations. This is a fixed release restriction, not a payment activation flag.
- Pending payments, deposit request, deduction and refund controls cannot be used.
- Existing reservation creation, editing, confirmation, cancellation, no-show and
  service blocking remain on the existing server contracts.
- Reservation/payment models, routes, capacity, hours, closures and scoring are
  unchanged. No migration or live reservation/payment test is part of deployment.
- Desktop reuses the isolated credential setup tested in the local candidate.
  Credentials are encrypted per Windows user; no server .env is distributed.
  The desktop IPC also rejects unfinished financial and completion endpoints.

Do not merge the unrelated dirty payment/legal/pacing development tree to ship
this release. Those features require their own coordinated validation.

Verification: 115 Jest checks (17 suites), 32 payment regression checks;
Chromium and WebKit synthetic fixtures on desktop 1440/1280 and admin 1024/390.
Disabled clicks make no financial requests; fixture confirmation remains usable.
Backend business files have no diff against the base. Fonts/logo load locally.

Keep DEPOSIT_ENABLED unchanged. Publishing this UI is not approval for LIVE
payments, automated Techfive posting or the proposed new service waves.
Installed desktop executables require distribution of a rebuilt binary;
a source push alone does not update restaurant PCs.
